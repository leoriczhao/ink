一帧的真实生命周期

读 ink 的第一个动作，是把“画图函数”从“立即执行”这个直觉里拿出来。这里的一帧是一次命令缓冲构建和提交。

入口: Surface 拥有整条链路

Surface 构造时拿到一个 Renderer，自己持有 Device，再创建指向这个 Device 的 Canvas。 所以你可以把 Surface 看成“前端命令构建器 + 后端执行器”的拥有者。 

// src/surface.cpp:11-15
Surface::Surface(std::shared_ptr<Renderer> renderer,
                 std::unique_ptr<Pixmap> pixmap)
    : device_(),
      renderer_(std::move(renderer)),
      pixmap_(std::move(pixmap)) {
    canvas_ = std::make_unique<Canvas>(&device_);
}

阅读任务

  1. 先看 include/ink/surface.hpp:29 的成员声明。
  2. 确认 Surface::MakeRaster 创建 CpuRenderer 和 Pixmap。
  3. 确认 Surface::MakeGpu 在 context 无效时回退到 raster。
结论: Canvas 不拥有像素，也不拥有 GPU 资源。它只是通往 Device 的用户侧 API。

四阶段帧协议

这四个函数共同定义了 ink 的帧协议。真正的执行点是 flush()，不是 draw 调用，也不是 endFrame()。 

// src/surface.cpp:57-74
void Surface::beginFrame(Color clearColor) {
    device_.beginFrame();
    if (renderer_) {
        renderer_->beginFrame(clearColor);
    }
}

void Surface::endFrame() {
    device_.endFrame();
}

void Surface::flush() {
    auto recording = device_.finishRecording();
    if (!recording || !renderer_) return;

    DrawPass pass = DrawPass::create(*recording);
    renderer_->execute(*recording, pass);
    renderer_->endFrame();
}

逐行解释

  1. beginFrame: 清空旧 recorder，同时让 renderer 清屏。
  2. endFrame: 只把 recorder 封成 recording，不执行。
  3. flush: 取走 recording，生成 DrawPass，调用 renderer。
  4. renderer->endFrame: 在 execute 后调用，GL 后端会 flush batch。
检查点: 在 endFrame() 后、flush() 前读 raster surface 的 pixels，理论上还看不到新绘制结果。
检查点: MakeRecording() 创建的是没有 renderer 的 surface，所以 flush() 会直接返回。

Canvas 是 facade，不是 rasterizer

Canvas 的简单 draw API 只是把颜色参数包成 Paint，然后转给 Device。这里没有 pixel loop，也没有 GL draw call。 

// src/canvas.cpp:10-17, 63-64
void Canvas::fillRect(Rect r, Color c) {
  device_->fillRect(r, Paint::Fill(c));
}

void Canvas::drawLine(Point p1, Point p2, Color c, f32 width) {
  device_->drawLine(p1, p2, Paint::Stroke(c, width));
}

void Canvas::drawPath(const Path &path, const Paint &paint) {
  device_->drawPath(path, paint);
}

读法

  1. 看到 Canvas 的 draw 函数，下一跳总是 Device。
  2. 如果涉及状态，先看 current_ 和 stack_。
  3. 如果涉及像素，直接跳到具体 Renderer visitor。
容易误解: Canvas::clipPath 会立即记录一个 clip op，但 clip 的实际几何实现仍在 renderer。CPU 生成 mask，GL 写 stencil。

Canvas 状态如何变成命令

save/restore 只在 Canvas 本地保存状态；每次恢复后，Canvas 会重新把 transform/clip 状态发给 Device，Device 再记录成 op。 

// src/canvas.cpp:82-90, 143-163
void Canvas::restore() {
  if (stack_.empty())
    return;
  current_ = stack_.back();
  stack_.pop_back();
  applyTransform();
  applyClip();
}

void Canvas::applyClip() {
  if (current_.hasClip || !current_.pathClips.empty()) {
    device_->resetClip();
  }
  if (current_.hasClip) {
    device_->setClipRect(current_.clip);
  }
  for (const auto &path : current_.pathClips) {
    device_->setClipPath(path);
  }
}

void Canvas::applyTransform() {
  if (current_.transform.isIdentity()) {
    device_->clearTransform();
  } else {
    device_->setTransform(current_.transform);
  }
}

要验证什么

  1. restore() 可能记录多个 op，而不是只改一个 C++ struct。
  2. applyClip() 会先 resetClip() 再重放当前 clip 列表。
  3. 这解释了为什么 DrawPass 必须把 clip/transform 当作 group boundary。

Renderer 接口是执行边界

所有后端都要实现同一个 Renderer 接口。CPU renderer 的 execute 是 visitor 分发；GL 后端也是 visitor 分发，只是 visitor 方法内部变成 GL 状态和 draw call。 

// include/ink/renderer.hpp:25-52
class Renderer {
public:
    virtual ~Renderer() = default;
    virtual void beginFrame(Color clearColor) = 0;
    virtual void endFrame() = 0;
    virtual void execute(const Recording& recording,
                         const DrawPass& pass) = 0;
    virtual void resize(i32 w, i32 h) = 0;
    virtual std::shared_ptr<Image> makeSnapshot() const = 0;
    virtual void setGlyphCache(GlyphCache* cache) { (void)cache; }
};
