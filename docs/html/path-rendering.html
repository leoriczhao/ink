Path 是学习 2D 渲染的主战场

ink 的 Path 子系统把图形开发最核心的东西串起来了：路径数据结构、曲线 flatten、fill rule、抗锯齿 coverage、stroke-to-fill、dash effect、clip mask。

Path 本身只是结构化几何数据

Path 不是像素，也不是 draw call。它保存 verb 序列和 points。渲染时才解释这些 verb。 

// include/ink/path.hpp:40-148
class Path {
public:
  enum class Verb : u8 {
    Move, Line, Quad, Cubic, Conic, Close,
  };

  Path &moveTo(f32 x, f32 y);
  Path &lineTo(f32 x, f32 y);
  Path &quadTo(f32 x1, f32 y1, f32 x2, f32 y2);
  Path &cubicTo(f32 x1, f32 y1, f32 x2, f32 y2,
                f32 x3, f32 y3);
  Path &conicTo(f32 x1, f32 y1, f32 x2, f32 y2, f32 weight);
  Path &close();

  const std::vector<Verb> &verbs() const { return verbs_; }
  const std::vector<Point> &points() const { return points_; }
  const std::vector<f32> &conicWeights() const { return conicWeights_; }

private:
  std::vector<Verb> verbs_;
  std::vector<Point> points_;
  std::vector<f32> conicWeights_;
  FillRule fillRule_ = FillRule::Winding;
};

读法

  1. 每个 verb 消耗的 point 数不同。读 rasterizer 时要跟着 ptIdx 走。
  2. Close 不消耗 point，它连回 contour 起点。
  3. 一个 Path 可以包含多个 contour，例如 donut 是两个 circle。
第一原则: Path 的核心不是“形状名称”，而是“边界曲线集合”。圆、矩形、圆角矩形都可以只是 Path 的语法糖。

CPU rasterizer 的主循环

CPU path fill 的核心是 scanline rasterization。先把 path 变成边，再逐行计算覆盖率，最后 blend 到目标像素。 

// src/path_rasterizer.hpp:36-83
void addPath(const Path &path, const Matrix &transform) {
  const auto &verbs = path.verbs();
  const auto &pts = path.points();
  const auto &cws = path.conicWeights();
  i32 ptIdx = 0, cwIdx = 0;
  Point contourStart = {0, 0}, cur = {0, 0};

  for (auto v : verbs) {
    switch (v) {
    case Path::Verb::Move:
      contourStart = cur = transform.mapPoint(pts[ptIdx++]);
      break;
    case Path::Verb::Line:
      Point next = transform.mapPoint(pts[ptIdx++]);
      addLine(cur, next);
      cur = next;
      break;
    case Path::Verb::Quad:
      flattenQuad(cur, cp, end, kFlatTolerance);
      break;
    case Path::Verb::Cubic:
      flattenCubic(cur, c1, c2, end, kFlatTolerance);
      break;
    case Path::Verb::Close:
      addLine(cur, contourStart);
      cur = contourStart;
      break;
    }
  }
}

这里学到什么

  1. 曲线先 flatten 成线段，才进入 scanline。
  2. transform 在几何阶段应用，不是在像素阶段再映射。
  3. kFlatTolerance = 0.25f 是质量/性能权衡点。
// src/path_rasterizer.hpp:85-145
void rasterize(Pixmap *target, const Rect &clip, Color color,
               BlendMode blend, u8 opacity, bool antialias,
               FillRule fillRule, const Shader *shader, bool isBGRA,
               const u8 *clipMask = nullptr, i32 clipMaskStride = 0) {
  i32 subCount = antialias ? kAAFactor : 1;
  f32 subStep = 1.0f / subCount;

  for (i32 y = clipY0; y < clipY1; ++y) {
    std::fill(coverage.begin(), coverage.end(), 0.0f);

    for (i32 sub = 0; sub < subCount; ++sub) {
      f32 scanY = y + (sub + 0.5f) * subStep;
      fillScanline(scanY, clipX0, clipX1,
                   fillRule, coverage.data(), subStep);
    }

    if (shader) {
      shader->shadeSpan(clipX0, y, width, shaderColors.data());
    }

    for (i32 i = 0; i < width; ++i) {
      Color src = shader ? shaderColors[i] : color;
      src.a = static_cast<u8>(src.a * covAlpha / 255);
      Color dst = decodePixel(pixel, isBGRA);
      pixel = encodePixel(blendColors(src, dst, blend), isBGRA);
    }
  }
}

这里学到什么

  1. AA 通过 8x y 方向 supersampling 得到 coverage。
  2. shader 只负责产出颜色，coverage 仍由几何决定。
  3. clipMask 会继续缩放 src alpha。

FillRule: inside 判断不是唯一的

同一个 path 数据，用 winding 和 even-odd 会得出不同的“内部区域”。这不是视觉选项，而是几何规则。 

// src/path_rasterizer.hpp:242-268
void fillScanline(f32 scanY, i32 clipX0, i32 clipX1,
                  FillRule fillRule, f32 *coverage, f32 weight) {
  thread_local std::vector<XIntersect> xInts;
  xInts.clear();

  for (const auto &e : edges_) {
    if (scanY < e.yTop || scanY >= e.yBot)
      continue;
    f32 x = e.xAtTop + (scanY - e.yTop) * e.dxPerY;
    xInts.push_back({x, e.winding});
  }

  std::sort(xInts.begin(), xInts.end(), byX);

  i32 winding = 0;
  for (size_t i = 0; i < xInts.size(); ++i) {
    i32 prevWinding = winding;
    winding += xInts[i].winding;

    bool wasFilled = (fillRule == FillRule::EvenOdd)
        ? (prevWinding & 1) != 0
        : prevWinding != 0;
    bool isFilled = (fillRule == FillRule::EvenOdd)
        ? (winding & 1) != 0
        : winding != 0;
  }
}

实验

  1. 构造两个同心 circle。
  2. 先用默认 Winding，看中心是否被填充。
  3. 设置 path.setFillRule(FillRule::EvenOdd)，再看中心是否变空。
源码锚点: examples/example_paths.cpp:83-90 的 donut 示例就是这个规则的实际用法。

Stroke 不是直接 rasterize，而是先变成 fill

当前 CPU path stroke 走 stroke-to-fill。也就是说“线宽、cap、join、miterLimit”先变成一个新的填充路径，然后复用 fill rasterizer。 

// src/cpu_renderer.hpp:316-329
void visitStrokePath(const Path &path, Color color, f32 width,
                     BlendMode blend, u8 opacity, u8 cap, u8 join,
                     f32 miterLimit, bool antiAlias,
                     const Shader *shader, const ColorFilter *) override {
  Path stroked =
      StrokeEngine::strokePath(path, width,
                               static_cast<LineCap>(cap),
                               static_cast<LineJoin>(join),
                               miterLimit);
  rasterizer_.reset();
  rasterizer_.addPath(stroked, currentTransform_);
  rasterizer_.rasterize(target_, effectiveClip(), color, blend,
                        opacity, antiAlias, FillRule::Winding,
                        shader, isBGRA_, clipMask, clipMaskWidth_);
}

读 StrokeEngine

  1. src/stroke.hpp:27-38: 先 flatten 成 contours。
  2. src/stroke.hpp:170-178: 计算 segment direction 和 normal。
  3. src/stroke.hpp:185-217: 构造 left/right offset polyline。
  4. src/stroke.hpp:219 之后: 把 offset polygon 写成 Path。
主动怀疑点: stroke-to-fill 简化了 renderer，但会把 stroke 的质量、join/cap 精度、退化线段处理都集中到 StrokeEngine。不要把它当成“天然正确”。

Dash effect 在记录期改变几何

PathEffect 的 dash 不是 renderer state。Recorder 在存 path 前调用 filterPath()，把原始 path 转换成一段段 on/off 线段。 

// src/path_effect.cpp:151-163, 209-239
class DashPathEffect final : public PathEffect {
public:
  Path filterPath(const Path &src) const override {
    Path out;
    out.setFillRule(src.fillRule());
    for (const auto &contour : flattenPath(src)) {
      dashContour(contour, out);
    }
    return out;
  }

private:
  void dashContour(const FlatContour &contour, Path &out) const {
    State state = initialState();
    for (size_t i = 0; i < segmentCount; ++i) {
      while (consumed < len) {
        f32 take = std::min(state.remaining, len - consumed);
        if (state.on && take > 1e-6f) {
          out.moveTo(p0);
          out.lineTo(p1);
        }
        consumed += take;
        state.remaining -= take;
      }
    }
  }
};

验证点

  1. tests/test_path.cpp 里有 dash 生成 on segments 的测试。
  2. dash effect 会 flatten 曲线，所以曲线 dash 精度由 flatten tolerance 决定。
  3. 因为它改变几何，fill rule 会被复制到输出 path。

clipPath: CPU mask 和 GL stencil 是两套实现

Path clip 是理解 backend 差异的好例子。CPU backend 生成 alpha mask 并乘到后续像素；GL backend 用 stencil bits 表达 clip。
